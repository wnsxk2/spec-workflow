# 시간 규칙은 서버 시계로 판단하고, Redis 보관 시간은 지난 기록을 치우는 데만 쓴다

세션 만료(30분), 유예 시간(10초), 로그인 차단(15분)은 Redis의 보관 시간(TTL)이 아니라, 서버가 기록해 둔 시각과 서버 시계를 비교해 판단한다. 테스트에서 시계를 바꿔 끼워 시간을 앞당겨 확인할 수 있어야 하기 때문이다. Redis 보관 시간만으로 판단하는 방식은 더 단순하지만 실제 시간을 기다려야만 확인할 수 있어 고르지 않았다.

## 결과

- 서버 시계와 Redis 보관 시간이 함께 쓰이는 경계가 있다. 서버 시계로는 유예 시간 안인데 Redis에서 새 Refresh Token의 원래 값이 먼저 사라졌으면, 재사용 감지로 보지 않고 401만 돌려준다. 정상적인 재시도를 도난으로 오해하지 않기 위해서다.
