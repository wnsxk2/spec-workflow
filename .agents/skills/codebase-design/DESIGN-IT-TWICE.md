# 두 번 설계하라 (Design It Twice)

사용자가 선택한 깊게 만들기 후보에 대해 대안 인터페이스를 탐색하고 싶을 때 이 병렬 서브 에이전트 패턴을 사용한다. Ousterhout의 "Design It Twice"에 기반한다: 첫 아이디어가 최선일 가능성은 낮다.

[SKILL.md](SKILL.md)의 용어 **모듈**, **인터페이스**, **시임**, **어댑터**, **레버리지**를 사용한다.

## 절차

### 1. 문제 공간 정리

서브 에이전트를 띄우기 전에, 선택한 후보의 문제 공간을 사용자용으로 설명한다:

- 새 인터페이스라면 무엇이든 만족해야 할 제약
- 의존하게 될 의존성과 그 분류([DEEPENING.md](DEEPENING.md) 참고)
- 제약을 구체화하기 위한 대략적인 예시 코드 스케치. 제안이 아니라 제약을 실감나게 만드는 수단일 뿐이다

이것을 사용자에게 보여 준 뒤 곧바로 2단계로 넘어간다. 서브 에이전트가 병렬로 작업하는 동안 사용자는 읽고 생각한다.

### 2. 서브 에이전트 생성

3개 이상의 서브 에이전트를 병렬로 띄운다. 각각은 깊어진 모듈에 대해 **근본적으로 다른** 인터페이스를 만들어 내야 한다.

각 서브 에이전트에게는 별도의 기술 브리프(파일 경로, 결합 상세, [DEEPENING.md](DEEPENING.md)의 의존성 분류, 시임 뒤에 놓이는 것)를 프롬프트로 준다. 이 브리프는 1단계의 사용자용 문제 공간 설명과는 별개다. 각 에이전트에게 서로 다른 설계 제약을 준다:

- 에이전트 1: "인터페이스를 최소화하라: 진입점은 최대 1~3개. 진입점당 레버리지를 극대화하라."
- 에이전트 2: "유연성을 극대화하라: 많은 사용 사례와 확장을 지원하라."
- 에이전트 3: "가장 흔한 호출자에 최적화하라: 기본 사례를 아주 쉽게 만들어라."
- 에이전트 4 (해당되는 경우): "시임을 가로지르는 의존성에 대해 포트와 어댑터를 중심으로 설계하라."

브리프에는 [SKILL.md](SKILL.md)의 용어와 GLOSSARY.md의 용어를 모두 포함해, 각 서브 에이전트가 아키텍처 언어와 프로젝트 도메인 언어에 맞게 이름을 짓도록 한다.

각 서브 에이전트의 산출물:

1. 인터페이스 (타입, 메서드, 매개변수, 그리고 불변식, 순서 제약, 오류 모드)
2. 호출자가 이를 어떻게 사용하는지 보여 주는 사용 예시
3. 구현이 시임 뒤에 숨기는 것
4. 의존성 전략과 어댑터 ([DEEPENING.md](DEEPENING.md) 참고)
5. 트레이드오프: 레버리지가 높은 곳과 얇은 곳

### 3. 제시와 비교

사용자가 하나씩 소화할 수 있도록 설계안을 순서대로 제시한 뒤, 문장으로 비교한다. **깊이**(인터페이스에서의 레버리지), **지역성**(변경이 집중되는 곳), **시임 배치** 기준으로 대조한다.

비교한 뒤에는 자신의 권고를 제시한다: 어느 설계가 가장 강력하다고 보는지와 그 이유. 서로 다른 설계의 요소를 결합하면 좋겠다면 하이브리드를 제안한다. 확실한 의견을 내라. 사용자는 메뉴판이 아니라 분명한 판단을 원한다.
