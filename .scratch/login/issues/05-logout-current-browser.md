# 05: 현재 브라우저에서 로그아웃하기

**만들 것:** 사용자가 로그아웃 버튼을 누르면 이 브라우저의 세션을 끝내고 로그인 화면으로 돌아간다. 정상적으로 로그아웃한 뒤에는 새로고침이나 보호된 화면 직접 접근으로 로그인이 복원되지 않으며, 다른 기기의 세션은 유지된다.

**Blocked by:** 02: 토큰 교환으로 새로고침 후 로그인 복원하기.

**Status:** ready-for-agent

**근거:** 로그인 spec의 사용자 스토리 11~13 및 ADR-0001.

## 인수 조건

- [ ] Refresh Token 쿠키로 로그아웃을 요청하면 해당 세션만 폐기하고 Refresh Token 쿠키를 삭제한다. 삭제에 사용하는 쿠키 이름·경로는 발급한 쿠키와 일치한다.
- [ ] 같은 사용자가 다른 기기에서 만든 세션은 폐기하지 않는다. 다른 세션의 Refresh Token으로 토큰 교환을 계속할 수 있다.
- [ ] Refresh Token이 없거나 알 수 없거나 세션이 이미 만료·폐기된 경우에도 로그아웃은 성공 응답과 쿠키 삭제를 반환한다. 반복 로그아웃도 성공한다.
- [ ] Redis가 멈춰 세션을 폐기할 수 없어도 로그아웃은 성공 응답과 쿠키 삭제를 반환한다. 이때 남은 서버 세션에는 spec의 세션 만료 규칙이 적용된다.
- [ ] 화면은 화면 인증 모듈을 통해 로그아웃을 요청하고 메모리의 Access Token을 즉시 지운다. 서버 요청의 성공·실패와 관계없이 로그아웃 상태를 화면에 알려 로그인 화면으로 안내한다.
- [ ] 정상 응답을 받은 로그아웃 이후 새로고침해도 로그아웃 상태다. 보호된 화면 주소로 직접 이동해도 로그인 화면으로 안내된다.
- [ ] 이미 발급된 Access Token은 ADR-0001에 따라 자신의 만료 시각까지 유효하다. 로그아웃 즉시 Access Token을 무효화하거나 보호된 요청에서 세션을 조회하지 않는다.
- [ ] 서버 HTTP API 테스트에서 실제 PostgreSQL·Redis로 현재 세션 폐기·쿠키 삭제, 폐기한 세션의 토큰 교환 실패, 다른 세션의 교환 성공을 확인한다. 없는·알 수 없는·만료된 토큰과 반복 요청의 성공도 확인한다.
- [ ] 테스트용 Redis를 실제로 멈춰 로그아웃 성공과 쿠키 삭제를 확인한다. 별도로 로그아웃 전에 발급한 Access Token의 유효 기간이 유지되는지 확인하며, Redis 내부 값 대신 HTTP 결과로 판정한다.
- [ ] 화면 인증 모듈 테스트로 서버 성공·실패·네트워크 오류 각각에서 메모리의 Access Token을 지우고 상태를 알리는 동작을 확인한다. 서버 응답을 받지 못한 경우의 쿠키 삭제까지 성공했다고 간주하지 않는다.
- [ ] E2E 시나리오 4인 "로그아웃 → 로그인 화면 → 새로고침 → 보호된 화면 직접 접근"을 실제 브라우저와 실제 저장소로 통과시킨다. 각 단계에서 로그아웃 상태를 확인한다.
- [ ] 테스트 이름·기댓값은 용어집과 spec을 따르고, 실행 명령·결과와 미검증 항목을 기록한다.
